# M0 — Establish Baselines

This milestone defines independent reference builds before integration. The [baseline definition](baseline.md) is the authority for revisions, comparison parameters, and acceptance scope; this document tracks the corresponding planning artifacts.

## Deliverables

- [x] Fix the four reference revisions and their roles in `baseline.md`.
- [x] Separate standalone arcade validation from PCEE2's ordinary PS2 core validation.
- [x] Define bounded startup, progress, shutdown, and core-unload checks.
- [x] Define the initial System246 case and the limits of M0 acceptance.

These items describe documentation delivered by the project. They do not publish local test results or certify a particular machine or graphics backend.

## Acceptance and handoff

Build PCSX2x6 and PCEE2 from the selected source revisions without modifying emulation behavior for the check. Exercise PCSX2x6 with its complete arcade inputs and PCEE2 with content it already supports. Record build identity, required resources, a short checkpoint, normal shutdown, and relevant limitations in the local validation record.

M1 may proceed once these independent build and lifecycle checks have been accepted. Correct video, audio quality, gameplay input, reload, and wider compatibility are separate checks in later milestones.

## Reference maintenance

Keep the source pins stable during integration. An upstream fix or a working fork does not automatically replace a baseline revision. Record any chosen update, why it is needed, and the affected checks before adopting it.
