# M2 — Boot One System246 Game

Status: scope outlined; expand implementation TODOs after M1. Entry condition: [M1](M1.md) provides a real, recoverable VM lifecycle.

## Goal

Reach the standalone startup checkpoint for NM00002, Bloody Roar 3, through the libretro Host. Preserve x6's `.acgame` boot behavior at the revision selected in the [baseline definition](baseline.md).

## Planned work

- [ ] Trace the `.acgame` request from the libretro ABI through existing x6 VMManager code without adding a second manifest parser.
- [ ] Preserve board selection, BIOS, ELF/arguments, dongle, CD media, and JVS mode.
- [ ] Preserve arcade identity, GameDB settings, patches, memory/clocks, IOP and DEV9 setup.
- [ ] Map SRAM/cards and other writable data to the core's persistent-data directory without altering original inputs.
- [ ] Add minimum frame readback/presentation if needed to identify the checkpoint.
- [ ] Report missing boot inputs as recoverable errors and preserve shutdown/persistence order.
- [ ] Review the handoff to M3.

## Acceptance boundary

Use the complete reference case, reach the agreed visible checkpoint, and close normally. Logs must identify the selected game, board, resources and patches. Missing BIOS, ELF, dongle, and media must fail with useful diagnostics and permit another load.

This milestone does not claim usable audio, complete input, additional games, or System256/HDD coverage. Local execution outcomes remain outside the repository. Detailed work items and any hooks brought forward from M3 will be recorded here before implementation.
