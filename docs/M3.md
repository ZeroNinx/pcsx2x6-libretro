# M3 — Basic Video, Audio, and Input

Status: M3.1 and M3.2 are complete; M3.3–M3.6 have not started. [M2](M2.md) supplies the recoverable arcade VM and minimum video path.

## Goal and scope

Make NM00002 Bloody Roar 3 usable through RetroArch: a correctly described image, audible stereo output, two-player fighting JVS controls, reset, and safe pause/resume and content reuse. Preserve the selected standalone behavior and the system/save directory contract.

Retain the CPU worker, separate GS thread, Vulkan Surfaceless device and synchronous MTGS readback. Hardware-image delivery, GPU download optimization, border cropping and GS ownership changes remain separate work. Savestates, rewind, runahead, netplay and additional arcade peripherals are outside M3's acceptance boundary.

## Execution and callback contract

Normal execution follows this order:

1. The frontend polls input and publishes a complete snapshot with a frame request.
2. The CPU thread consumes that request and applies the snapshot before advancing emulation. Successful VM initialization stays parked until the first request.
3. At the next emulated vsync, the CPU thread submits ordered GS readback, completes the image and captures the audio boundary and current timing.
4. Completed-frame state is published before the frontend is notified. The CPU waits for the next request while still servicing commands and stop requests.
5. The frontend announces any AV changes, presents the completed image and submits only the audio belonging to that completion.

Frame requests and completions have an explicit sequence. A request must not both acknowledge one frame and authorize an unrequested next frame. Failed startup, reset, unload and reinitialization invalidate obsolete frame, input and audio state. No frontend callback runs on CPU, GS or an audio worker, and no GS wait holds the session lock. VM transitions remain CPU-thread operations.

The request/completion handshake keeps emulation parked between frontend requests while preserving GS queue ownership. Core boots set `VMBootParameters::start_unlimited=true`, selecting Unlimited mode and bypassing VM throttling. Device VSync stays disabled through `VsyncEnable=false`; RetroArch controls normal pacing and fast-forward.

## M3.1 — Frame requests and ownership

- [x] Establish the request/completion contract above, including the first frame and steady-state requests, command processing while parked, stop without another `retro_run`, and session reuse. M2's completion-then-token-consumption overlap occurs in steady state as well as startup.
- [x] Set `VMBootParameters::start_unlimited` for core boots and remove the ineffective `FrameLimitEnable` setting. Keep the VM limiter Unlimited across normal execution and reset; RetroArch controls normal pacing and fast-forward. Retain `VsyncEnable=false`.
- [x] Verify Unlimited mode and zero target throttle speed, then run a short unpaced harness check and RetroArch normal/fast-forward checks. With sufficient workload headroom the unpaced harness should exceed the nominal refresh rate. If it does not, inspect limiter state and throttle waits rather than treating GPU or CPU saturation as proof of an active limiter; this is a pacing check, not a performance target.
- [x] Define completed-frame metadata: sequence, pixel dimensions and pitch, display aspect and emulated vsync frequency. The frequency is published at every completion, including frames without an image; the audio boundary joins this metadata together with the audio stream in M3.3. Keep pixel storage valid until the video callback returns.
- [x] Publish timing and device-derived metadata from its owning thread rather than reading live VM or GS state on the frontend.
- [x] Define both the validated frame/allocation limit and the initially advertised AV maximum dimensions before replacing fixed geometry, accounting for the configured upscale factor and deinterlacing output. Specify when a legitimate mode change requires new maximum dimensions through `SET_SYSTEM_AV_INFO`; `SET_GEOMETRY` cannot enlarge the frontend's allocation. Keep the existing wait diagnostics and rollback behavior. The core fixes the upscale multiplier at 1, so the largest GS display mode, 1080i at 1920×1080, bounds every composed frame; the session rejects larger frames and the AV information advertises that maximum from the start. While the multiplier stays fixed, no display mode needs a larger maximum.

Relevant code: `libretro/LibretroSession.{h,cpp}`, `libretro/Libretro.cpp`, and the existing `Counters.cpp` → Host pump boundary. Stop and queued commands must work even when no further frame is requested.

## M3.2 — Video geometry and timing

- [x] Carry dimensions with each image instead of assuming every buffer is 640×480. Initially use the existing snapshot interface with zero requested dimensions and aspect correction disabled to obtain the current GS composite texture dimensions without the fixed-canvas rescale. Confirm the exact result before treating it as the output contract.
- [x] Keep output pixel dimensions separate from display aspect ratio. A composed texture may include upscaling or deinterlacing and is not necessarily the game's native framebuffer. Preserve the GS image, including existing borders; do not infer a crop from black pixels.
- [x] Retain XRGB8888 conversion and buffer ownership. Validate dimensions, pixel count, pitch and allocation limits; a missing first image produces black, and a later temporary failure may repeat only the current session's last valid frame.
- [x] Report the actual emulated vsync frequency, not internal game FPS or measured execution speed. Use `GetVerticalFrequency()` and the selected GS aspect policy through owned metadata; keep the nominal pre-boot values only until real timing exists.
- [x] Announce geometry/aspect-only changes with `RETRO_ENVIRONMENT_SET_GEOMETRY` when within the advertised maximum; use `SET_SYSTEM_AV_INFO` for timing, sample-rate or maximum-size changes. Make callbacks from the frontend before delivering the affected output and diagnose rejected required changes.

Relevant code: the session capture path, `pcsx2/MTGS.cpp`, `pcsx2/GS/Renderers/Common/GSRenderer.cpp`, and `pcsx2/GS.h`. Add a GS hook only for a demonstrated functional limitation of the existing interface.

The session submits one GS job per completed frame that takes the snapshot with zero requested dimensions, aspect correction and border cropping disabled, and reads the display aspect ratio. With the default zero crop, that snapshot is the composite texture at its own size: the PCRTC display resolution times the fixed upscale multiplier, after any deinterlacing. The aspect ratio comes from `GSGetDisplayAspectRatio()`, a GS-thread query of the aspect ratio setting and current video mode. It is the one emulator-side addition, because that policy and the progressive-mode state it depends on are private to the GS renderer.

The vsync frequency is `GetVerticalFrequency()` on the CPU thread. It is not published while the video mode is still uninitialized, because the emulator then only has a placeholder value. The frontend compares frame rates at single precision, the precision of the emulator's frame rate settings. Before it presents a frame, it announces a timing change with `SET_SYSTEM_AV_INFO`, and a size or aspect change alone with `SET_GEOMETRY`. The core keeps the AV information the frontend has accepted: it starts from the initial values when content loads or unloads, changes only when an update succeeds, and is what `retro_get_system_av_info` returns. A geometry update leaves the accepted timing unchanged. A rejected update is retried with later frames and logged once per distinct request; frames continue to carry their own size meanwhile.

## M3.3 — Audio delivery

- [ ] Add a focused SPU2 output-stream factory or equivalent Host seam. The imported x6 revision has no `CustomOutputStreamFactory`; PCEE2's hook is a reference to adapt, not an existing interface. Preserve SPU2 mixing, volume and stream lifetime.
- [ ] Use a stereo output path without opening a host audio device. Adapt `AudioStream` using `AudioSynchronizationMode::Disabled`; add only the access needed to drain actual buffered samples, avoiding underrun resampling caused by requesting samples that do not exist.
- [ ] Use one core volume value to set both `SPU2/Output/StandardVolume` and `FastForwardVolume` explicitly in `ApplyCoreSettings()`, initially 100. Unlimited has target speed 0, so SPU2 selects its fast-forward volume when unmuted; setting only the standard volume would not control normal frontend-paced playback. Preserve mute behavior and verify the effective volume with a nondefault value and after stream recreation.
- [ ] Convert the stream's floating-point stereo samples to interleaved signed 16-bit samples with clipping. Capture the committed-sample boundary at each completed vsync and transfer owned audio to the frontend. Account for the existing 64-frame SPU2 chunks and retain partial chunks across frame boundaries; do not invent a fixed 800-sample budget per frame.
- [ ] Bound total frontend audio backlog to 250 ms at the active sample rate. Handle partial or zero acceptance from the batch callback without spinning, unbounded allocation, or consuming audio beyond the published boundary. On overflow, drop and count the oldest unaccepted frames so recovery does not replay an expanding delay; preserve the order of retained audio. Distinguish produced, accepted, retained and dropped frames.
- [ ] Report the active stream sample rate. A rate change, accepted reset or new session must not mix old-rate audio with new output. Clear queues at lifecycle boundaries and release stream references before their VM owner is destroyed.

Relevant code: `pcsx2/SPU2/spu2.{h,cpp}`, `pcsx2/Host/AudioStream.{h,cpp}`, and a separate frontend audio adapter under `libretro/`. Test with the actual sound of the selected title; nonzero buffers alone do not establish audible correctness.

With synchronization disabled, `OnTargetSpeedChanged()` clears the stream buffer and the partial SPU2 chunk. Do not change the VM limiter mode for frontend fast-forward; if a real target-speed transition occurs, account for that discarded stream data rather than filling an assumed per-frame sample budget. `GetNominalRate()` remains 1.0 when host-speed adjustment is inactive, and `SetTargetSpeed(0)` does not enable audio time stretching in Disabled mode. The adapter drains only committed samples.

The 250 ms limit is storage capacity, not a prefill requirement or a latency target.

## M3.4 — JVS input

- [ ] Register two joypad ports and frontend input descriptions. Poll only on the frontend thread; apply complete snapshots on the CPU thread using the frame contract from M3.1.
- [ ] Reuse `ACJV::SetButtonState`, `InsertCoin` and current layout/binding metadata. Preserve x6's GameID-selected Bloody Roar layout and JVS protocol; avoid a second game-layout database or frontend writes into JVS globals.
- [ ] Apply directions, Start and action buttons as levels. Coin is a rising-edge event per slot; Service remains an independent level control. Global Test toggles the existing Test Mode DIP once per press, following x6's DIP semantics.
- [ ] Keep Test as an in-memory DIP: new content loads the configured default (off), while an ordinary reset preserves the current DIP state. `ApplySettings()` reloads DIP configuration through `ACJV::LoadConfig()`, including when reached by `UpdateDiscDetails()` or a game-settings reload. Avoid unnecessary whole-settings reloads during a session; do not use one to apply frontend-only frame or input changes.
- [ ] Release controls on disconnect and content close. Reset/reconnect must not synthesize coin or Test events from a button already held; require release before rearming those edges. Frontend pause/resume must not duplicate an edge.
- [ ] Prevent disabled native SDL/DInput/XInput/RawInput sources from initializing or republishing input. Keep the change focused on respecting disabled sources and preserve independent source behavior for upstream comparison.

Default NM00002 mapping, subject to a short functional check before completion:

| RetroPad control | JVS action |
| --- | --- |
| D-pad | Player directions |
| Y / B / A / X | Punch / Kick / Beast / Block |
| Start | Player Start |
| Select | Coin for that player's slot, on press |
| L3 | Player Service |
| Port 1 R3 | Global Test Mode toggle, on press |

Ports 1 and 2 use their corresponding player/coin slot; only port 1 owns the global Test action. Action positions follow x6's Bloody Roar defaults: Square / Cross / Circle / Triangle. Full racing, lightgun, drum, touch and cabinet output support is later work.

## M3.5 — Pause, reset and reuse

- [ ] Treat ordinary frontend pause as absence of frame requests: the CPU parks at its frame boundary and no new audio/video is submitted. Resume samples current input before advancing. libretro has no general `retro_pause` entry point; do not add an unnecessary public pause option.
- [ ] Verify the existing CPU-thread pause/resume command path separately. If the VM is explicitly paused, a frame wait must finish without advancing the VM or hanging; stop and reset must remain serviceable.
- [ ] Implement `retro_reset` through the CPU queue and `VMManager::RequestReset()`. Respect memory-card-busy refusal and the deferred `Resetting` path; do not acknowledge completion until the reset actually occurred, or discard output state when a reset was rejected. Preserve the prior running/paused intent.
- [ ] Invalidate pre-reset pixels and audio, release held input and rearm edge controls safely. Preserve SRAM, BIOS working data and cards according to x6 semantics; reset is not a replacement content load or a save-file deletion.
- [ ] Check reset with Test Mode enabled: releasing the input trigger must not clear the DIP, and an ordinary reset must retain it. A new content session loads the default instead. If a reset explicitly reapplies settings, such as the upstream hardcore-mode transition, retain that configuration-reload behavior rather than promising unconditional DIP preservation.
- [ ] Cover startup failure, close/reopen, active deinit and same-module deinit/init with the new media state. Stop and deinit must not require the frontend to accept more audio or call `retro_run` again.

## M3.6 — Functional acceptance and M4 handoff

- [ ] NM00002 reaches one short interactive checkpoint: a coin changes credit, Start proceeds, directions and Punch/Kick/Beast/Block respond, and P1/P2 routing remains distinct. Use a disposable save copy for Service/Test checks and leave the cabinet in a normal mode afterward.
- [ ] The picture has correct color, orientation and display aspect; geometry/timing reporting follows actual output. Existing borders are recorded without automatic cropping.
- [ ] Real game audio is audible, correctly paced and free of a reproducible integration-induced pitch/channel problem. Short callback-stall checks establish bounded buffering, partial acceptance and recovery; arithmetic counts supplement listening.
- [ ] Pause/resume, reset, close/reopen and same-module reinitialization retain the frame/input/audio association and M1/M2 shutdown and save-safety guarantees. Repeat only earlier resource-failure checks affected by the implementation.
- [ ] Record the accepted backend, geometry/aspect policy, timing, sample format/rate, controls and limitations as the functional reference for M4. Keep local results and evidence outside this repository.

Stop after the required controls, audiovisual behavior and normal shutdown are confirmed. NM00054 remains a short System256/HDD and state-reuse regression case, not an additional playable-game requirement.
