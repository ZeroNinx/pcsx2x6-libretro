# M5 — Performance and Compatibility

Status: candidate scope only; select and expand individual workstreams after the functional baseline and relevant M4 decisions.

## Goal

Improve a specified workload or add a defined platform, board, media, or peripheral case without weakening the established baseline.

## Candidate workstreams

- [ ] CPU/GS/MTVU efficiency and additional graphics backends.
- [ ] System256/Super256 and additional CD/DVD/HDD arrangements.
- [ ] ARM64 and additional supported frontend/platform combinations.
- [ ] VFS integration and resource packaging where the target platform requires them.
- [ ] Lightguns, wheels, drums, touch input, and other arcade devices.

These are candidates, not a requirement to implement every item. Each selected workstream needs its own problem statement, affected interfaces, small TODOs, comparison case, and acceptance criteria before implementation.

## Acceptance boundary

Performance work demonstrates its claimed benefit on a specified workload. Compatibility work identifies the exact game/device and standalone behavior used for comparison. A successful case does not imply full board or peripheral coverage.

Record reusable implementation decisions in this document or linked workstream documents. Keep machine-specific execution results and troubleshooting history in local records unless publication is explicitly requested.
